# 작업 리뷰

현재 작업의 변경분과 직접 연결된 부분을 대상으로 다음을 확인한다. 적용되지 않는 항목 때문에 별도 작업을 만들지 않는다.

| 기준 | 확인할 내용 |
|---|---|
| 스펙 일치 | 승인된 동작 규칙과 예외 처리가 구현됐는가 |
| 작업 범위 | 필요한 변경이 빠졌거나 요청하지 않은 변경이 들어갔는가 |
| 정상 동작 | 작업의 완료 조건과 검증 방법을 충족하는가 |
| 기존 기능 영향 | 직접 연결된 기존 동작이 깨지는가 |
| FE/BE 연결 | 작업에 관련된 요청·응답·데이터·오류 처리가 합의된 계약과 맞는가 |
| 코드 품질 | 명백한 결함, 불필요한 복잡성, 기존 프로젝트 관례 위반이 있는가 |

실제 결함과 선택적인 개선 제안을 구분한다. 결함은 가능하면 구체적인 발생 조건, 영향, 관련 코드 위치를 근거로 보완한다. 추측성 개선으로 승인된 범위를 확장하지 않는다.

현재 작업 안에서 보완할 수 있으면 수정하고 필요한 검증을 다시 수행한다. 설계 또는 계획 변경이 필요하면 해당 단계 재확인을 요청한다. 해결되지 않은 문제나 실행하지 못한 검증을 숨기지 않는다.

리뷰 및 검증 결과는 `progress.yaml`의 해당 작업에 기록한다. 리뷰 통과와 사용자 확인은 별도이며, 리뷰를 통과해도 사용자 확인 전에는 다음 작업을 구현하지 않는다.
